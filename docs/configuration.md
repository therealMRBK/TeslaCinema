# Configuration

All settings live in the `.env` file next to `docker-compose.yml` (`./setup.sh` creates it). After a change:

```bash
docker compose up -d
```

## Reference

| Variable | Default | Meaning |
|---|---|---|
| `AUTH_USER` | `cinema` | User name of the login |
| `AUTH_PASSWORD` | *(generated by setup.sh)* | Password of the login. **Required**: the server refuses to start without one |
| `ALLOW_NO_AUTH` | `0` | `1` allows an empty password. Only if something else in front of it does the login |
| `BIND_ADDRESS` | `127.0.0.1` | `127.0.0.1` = only this machine, `0.0.0.0` = also your LAN (plain http) |
| `HOST_PORT` | `8195` | Port on the host |
| `LOCALE` | `en_US.UTF-8` | Container locale and language of Chrome's menus |
| `CHROME_LANG` | *(from LOCALE)* | Override Chrome's UI language, e.g. `de`, `fr`, `en-GB` |
| `DISPLAY_WIDTH` / `DISPLAY_HEIGHT` | `1920` / `1080` | Start size of the virtual screen (it then follows the viewer's browser window) |
| `AV_BITRATE` | `3500k` | Video bitrate of the stream |
| `AV_BUFSIZE` | `4M` | Rate-control buffer of the video encoder. Raise it (`6M`) if the log shows `rc buffer underflow` during fast motion |
| `AV_FPS` | `30` | Frame rate of the stream (MPEG-1 allows 24, 25, 30, 50, 60) |
| `AV_MAX_BEHIND_MS` | `400` | How far the viewer may lag before the stream jumps to the newest frame |
| `DOMAIN` | | Your domain, for the `caddy` profile |
| `CLOUDFLARE_TUNNEL_TOKEN` | | Token of your named tunnel, for the `cloudflared-token` profile |
| `COMPOSE_FILE` | *(set by setup.sh)* | Which compose files to use, e.g. `docker-compose.yml:docker-compose.gpu.yml` |
| `COMPOSE_PROFILES` | *(set by setup.sh)* | `caddy`, `cloudflared` or `cloudflared-token` |

## Picture quality

The stream is MPEG-1 video plus MP2 audio in one MPEG-TS stream. It is not the most efficient codec, which is the point:
it decodes in plain JavaScript in any browser, and it encodes in software without a GPU with little delay.

| Situation | Try |
|---|---|
| Stutters or freezes on mobile data | `AV_BITRATE=2000k` (or `1500k`), maybe `AV_FPS=24` |
| Blocky picture, but the connection is fast | `AV_BITRATE=6000k` |
| Server CPU too busy | smaller `DISPLAY_WIDTH`/`DISPLAY_HEIGHT` (for example 1280 x 720), `AV_FPS=24` |
| Text looks soft | Higher bitrate helps most. A resolution that matches the car screen avoids scaling |

Rule of thumb: the bitrate must be **below** the slowest link in the chain, usually the car's mobile data or your
home upload speed. Measure with a speed test on the machine that hosts it. If the line is too slow the stream skips ahead
to the newest picture instead of falling behind, which looks like short freezes: lower the bitrate then.

A data point from a test machine: 1280 x 720 at 30 fps, a video playing in Chrome, the stream watched by one viewer used
roughly 40 % of one CPU core and 550 MB RAM (whole container). 1080p needs more. Give it 2+ cores.

Since the virtual screen follows the size of the viewing browser window, a big viewer window costs more than a small one.

## Language

`LOCALE` accepts any of: `en_US de_DE fr_FR es_ES it_IT nl_NL pt_BR pl_PL tr_TR sv_SE da_DK nb_NO fi_FI cs_CZ`, each with
`.UTF-8` (for example `LOCALE=de_DE.UTF-8`). A UTF-8 locale is required: without one, typing umlauts, accents or emoji
fails. Need another one? Add it to the `localedef` list in the `Dockerfile` and rebuild.

## Persistent data

The Docker volume `teslacinema-data` holds Chrome's profile (logins, cookies, bookmarks) and the shared file folder.

```bash
# back it up
docker run --rm -v teslacinema-data:/data -v "$PWD":/backup alpine tar czf /backup/teslacinema-data.tgz -C /data .
# start with a clean Chrome (logs you out of everything)
docker compose down -v
```

## Several instances

Copy the folder, change `HOST_PORT`, and set a different project name: `docker compose -p cinema2 up -d`. Container names
are fixed (`teslacinema`): remove the `container_name` lines in the copy.
